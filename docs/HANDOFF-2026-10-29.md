# 0.1.0 交接 · 2026-10-29

## 当前交付

独立 Windows 桌面工程，分支 `codex/desktop-tagger`。四种标注格式、三种处理方式、原生 DSH、只读默认的 Agent HTTP/MCP、持久化编辑与备份已实现。目录版和单文件便携包在 `release/`，不跟踪到 Git；没有创建或推送 GitHub 仓库。

运行入口为 `release/win-unpacked/TK Dataset Studio.exe`。本机已创建「TK 数据集打标器」桌面快捷方式，并在该用户的应用数据中登记现有 MOAT 权重、已有 DSH 工作区及角色快照；这些本机路径、用户数据和测试图片不在源码中。

## 接手读取

先读 `AGENTS.md`、`CONTEXT.md`、`docs/VERIFICATION.md`。使用说明在 README，接口在 `docs/AGENT-API.md`，准确依赖在 lock。不要把 UI 草稿当作已保存预设；不要把任务过程文本当作最终标注。

## 已确认的关键问题与处理

- Relay 的 `task` 和 `content` 二选一。携带图片时使用 content 的文本+图片块；同时传 task 会丢失图片。本程序检查 taskImageCount。
- Relay 工作区必须是 DSH 已注册的精确路径；read/context scope 必须非空且只指向本次任务文件。通过公共 catalog 选择，不能篡改 Host 授权目录。
- 模型最终输出放在 `<<<TK_FINAL_PROMPT>>>` / `<<<TK_FINAL_PROMPT_END>>>` 协议中，单独解析纯最终稿。caption/hybrid 的 JSON 外壳只作内部草稿，不写进纯描述 TXT。
- Python embed 必须使用 CP312 wheel 和隔离 `_pth`。开发目录有一次失败安装留下的错误 ABI 目录，技术审核未允许清理，原样保留；包中已排除该目录，正确依赖是 site-packages-cp312。
- 第二实例拿锁失败后必须 return，单独 app.quit 不会停止模块执行；否则可能启动另一份后端并覆盖端点文件。真实 Electron 回归测试已覆盖。
- 角色资料只由 References 管理，统一标签键。查库关闭时不再注入缓存，源站更新不覆盖用户自己的资料。
- 同名 TXT 的 SHA、原图状态与 revision 要在写入边界验证；不要以重试覆盖并发编辑。未写入结果保存在历史供核对。

## 后续优先项

复杂拼贴中的语义对应仍需视觉审校；当前框线预览不能直接拖动改框。大目录导入可取消、历史 diff、便携路径变化后的长期 MCP 稳定入口是后续改进点。不要宣称语义已经完全保真，也不要为追求“通过”而隐藏模型失败或混入过程说明。
